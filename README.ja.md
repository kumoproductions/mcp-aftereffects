LLM に Adobe After Effects を操作させる。**mcp-aftereffects** は、MCP 対応クライアント（Claude Desktop、Claude Code、その他 stdio 対応の MCP クライアント）を、起動中の After Effects セッションへ接続します。モデルはプロジェクト状態の調査、アトミックな undo グループ単位でのコンポジションとレイヤーの編集、プロジェクト全体の JSON チェックポイントと復元、そしてフレームをレンダリングしての自己検証を、型付きのツール層を通じて行います（ExtendScript コンソールにアドホックなスクリプトを貼り付ける方式ではありません）。

> [English](README.md)

**得意なこと:**

- **コンポジション監査**（「`Main` の全レイヤーを列挙して、無効化されたエフェクト、欠落したフッテージ参照、エクスプレッションエラーがあれば指摘して」）
- **キーフレームとエクスプレッションの作業**（「レイヤー 3 の 0 秒から 2 秒にイージング付きの位置キーフレームを追加して、不透明度に wiggle エクスプレッションを付けて」）
- **JSON チェックポイントと復元**：リスクの高い変更の前にプロジェクト全体を JSON ドキュメントへスナップショットし、インポート 1 回で巻き戻します
- **レンダリングして確かめるループ**：変更し、`ae_render_frame` でフレームをレンダリングし、PNG を見て、修正し、繰り返す。モデルが自分の作業を視覚的に確認します

> [!CAUTION]
> **何が起きるかを理解してから先へ進んでください。** After Effects にライブ接続した LLM は、プロジェクトを読み取り、書き換え、そして（オプトインした場合）マシン上の任意コードを実行できます。具体的には次のとおりです。
>
> 1. **プロジェクトのデータはマシンの外に出ます。** コンポジション名とレイヤー名、エクスプレッションのソース、キーフレーム値、フッテージのファイルパスなど、LLM が `ae_project_info` / `ae_comp_info` / `ae_layer_info` / `ae_project_export_json` で読んだものはすべて、選択した LLM プロバイダへ送られ、MCP クライアント側でログに残る場合もあります。**NDA 下の案件や未発表の作品を扱うときは、プロバイダの保持ポリシーとクライアントのログが許容できるか、先にスタジオや法務へ確認してください。**
> 2. **LLM は書き込み権限を持ちます。** コンポジション、レイヤー、キーフレーム、エフェクト、マスク、エクスプレッションの作成、変更、削除ができます。各呼び出しは自動的に単一の undo グループの中で走るため、Ctrl+Z 一回でその呼び出しのプロジェクト変更が戻ります。ただし `ae_save_project` はディスク上のファイルを上書きしますし、プロジェクト外に書かれたファイル（レンダリングされた PNG、エクスポートされた JSON）は undo できません。`batch.run` は 1 呼び出しである点にも注意してください（50 オペレーションのバッチは Ctrl+Z 一回分です）。
> 3. **任意の ExtendScript はデフォルトで無効です。** `ae_do` 経由で呼ぶ `eval.run` オペレーションは、After Effects プロセスの全権限（ファイル I/O、`system.callSystem`、`Socket`）で無制限の ExtendScript を実行します。`AE_MCP_ENABLE_EVAL=1` を設定しているあいだだけ存在する、アトミックなオペレーションでカバーできない処理のための抜け道です。不要になったら無効へ戻してください。
>
> **`AE_MCP_READONLY=1` を設定すると 2 は無効になり、3 のオプトインよりも優先されます。** 1 はそれでも残ります（モデルはプロジェクトを読み取り、プロバイダへ送信できます）。[権限ポリシー](#権限ポリシー)を参照してください。
>
> 初回利用の前に、プロジェクトをバックアップ（またはコミット）し、使い捨ての `.aep` で試し、MCP クライアントの呼び出しごとの承認プロンプトを有効なままにしてください。

## 仕組み

```
MCP クライアント (Claude Code、Claude Desktop、…)
   │ stdio
   ▼
mcp-aftereffects  (Node.js)
   │ AfterFX.exe -r (Windows) / osascript (macOS)  +  ファイル IPC
   ▼
After Effects  (起動中のインスタンス)
```

After Effects 側にインストールするものはありません。プラグインもパネルもソケットも不要で、サーバーが既存の AE インスタンスを Windows では `AfterFX.exe -r`、macOS では AppleScript（`osascript` → `DoScript`）経由で駆動します（ツール呼び出し 1 回につき 1 往復）。各呼び出しは自動的に単一の undo グループの中で走るため、Ctrl+Z 一回がちょうど 1 呼び出し分の巻き戻しになります。トランスポートの内部構造は [CONTRIBUTING.md](./CONTRIBUTING.md) に記載しています。

## 動作要件

- **Windows または macOS。**
- **Adobe After Effects 2024、2025、2026 のいずれか。** 既定のインストール場所を自動で探します（2026 → 2025 → 2024 の順）。Windows は `C:/Program Files/Adobe/Adobe After Effects <year>/Support Files/AfterFX.exe`、macOS は `/Applications/Adobe After Effects <year>/Adobe After Effects <year>.app` です。別の場所にある場合は `AE_MCP_EXE` で指定します。
- **Node.js 24+。**
- **AE の環境設定「スクリプトによるファイルへの書き込みとネットワークへのアクセスを許可」（環境設定 → スクリプトとエクスプレッション）を ON にしてください。** OFF のままではすべての呼び出しがタイムアウトします。
- **macOS のみ: オートメーションの許可。** 最初の呼び出し時に、MCP クライアント（またはターミナル）が After Effects を制御してよいか macOS が確認します。許可してください。後から変更する場合は「システム設定 → プライバシーとセキュリティ → オートメーション」です。拒否されている場合、すべての呼び出しが `Not authorized` のトランスポートエラーで即座に失敗します。
- MCP 対応クライアント（例: Claude Code）。

## クイックスタート

1. **クローンしてビルドします:**

   ```
   git clone https://github.com/kumoproductions/mcp-aftereffects.git
   cd mcp-aftereffects
   npm install
   npm run build
   ```

2. **MCP クライアントへ登録します。** Claude Code の場合は `.mcp.json` に追加します（チェックアウトへの絶対パスを使います）:

   ```json
   {
     "mcpServers": {
       "aftereffects": {
         "command": "node",
         "args": ["/absolute/path/to/mcp-aftereffects/dist/index.js"]
       }
     }
   }
   ```

   パッケージが npm に公開されれば、`"command": "npx", "args": ["-y", "@kumoproductions/mcp-aftereffects"]` でローカルのチェックアウトなしに動きます。

3. **After Effects を手動で起動し、プロジェクトを開いて（または作成して）おきます。** トランスポートは既存の AE インスタンスを対象とし、ウォーム状態の呼び出しは 500 ms〜1 秒程度です。AE が起動していない場合は最初の呼び出しが AE をコールド起動しますが（10〜30 秒）、AE が何らかのユーザー操作を経るまでは不安定です。先に自分で AE を起動しておくのが確実です。

続けてこう試してみてください。

> 「このプロジェクトにはどんなコンポジションがある？ `Main` に赤い平面を追加して、確認できるようにフレーム 0 をレンダリングして。」

LLM は `ae_project_info` → `ae_do` → `ae_render_frame` の順に呼び出します。

## 環境変数

| 変数                      | レガシー別名 | デフォルト                                              | 備考                                                                                                                                                                       |
| ------------------------- | ------------ | ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AE_MCP_EXE`              | `AE_EXE`     | 既定のインストール場所から AE 2026 → 2025 → 2024 を探索 | Windows は `AfterFX.exe` へのフルパス、macOS は `.app` バンドル。AE が標準外の場所にあるときに設定します。                                                                 |
| `AE_MCP_READONLY`         | —            | 未設定（書き込み**有効**）                              | `1` でプロジェクトを変更しうるすべてをブロックします。[権限ポリシー](#権限ポリシー)を参照。                                                                                |
| `AE_MCP_ALLOW_CATEGORIES` | —            | 未設定（全カテゴリ）                                    | カンマ区切りの `ae_do` カテゴリ許可リスト。例: `keyframe,property,batch`。                                                                                                 |
| `AE_MCP_ENABLE_EVAL`      | —            | 未設定（`eval.run` **無効**）                           | `1` でレジストリに `eval.run`（任意の ExtendScript）を追加します。`AE_MCP_READONLY=1` の間は無視されます。                                                                 |
| `AE_MCP_RUNTIME_DIR`      | —            | `<OS temp>/mcp-aftereffects/runtime`                    | ファイル IPC メールボックスの場所を変更します。両側で一致している必要があります（サーバーが場所を公開し、AE 側がそれを見つけます）。テスト以外で必要になることはまれです。 |

### 権限ポリシー

独立した 3 つのスイッチです。`ae_catalog` は現在のポリシーが実際に実行するものだけを広告するため、モデルは「サーバーが壊れている」と誤解せず、実行できる範囲で計画を立てます。

| 設定                          | 効果                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AE_MCP_READONLY=1`           | `ae_save_project` と `ae_project_import_json` は登録されません。`ae_do` はプロジェクトを変更できないオペレーション（`property.get`/`list`、`layer.bounds`、`project.find_layers`、`marker.list`、`render.status`、`font.list`、`command.find`/`list` など、このモード中に `ae_catalog` が広告する読み取り専用セット、および読み取り専用の `batch.run` 子オペレーション）だけを受け付けます。`AE_MCP_ENABLE_EVAL` の値にかかわらず `eval.run` は無効のままです。 |
| `AE_MCP_ALLOW_CATEGORIES=a,b` | `ae_do` は列挙したカテゴリ外のオペレーションを拒否します。読み取り専用モードと組み合わせると、範囲を絞った監査セッションになります。                                                                                                                                                                                                                                                                                                                            |
| `AE_MCP_ENABLE_EVAL=1`        | レジストリに `eval.run`（任意の ExtendScript）を追加します。`AE_MCP_READONLY=1` が優先されます。未設定のデフォルトはサンドボックスでは**ありません**。`command.execute` は任意のメニューコマンドを実行できますし、書き込みオペレーションもすべて残ります。「プロジェクトに触らないでほしい」という意味なら `AE_MCP_READONLY=1` を使ってください。                                                                                                               |

`ae_render_frame` と `ae_project_export_json` は読み取り専用モードでも残ります。ファイルは書きますがプロジェクトには触れませんし、レンダリングして確かめるループこそが調査セッションの目的だからです。ここは文字どおりに読んでください。**読み取り専用が意味するのは「プロジェクトを変更しない」であって、「副作用がない」ではありません。** どちらのツールも渡された絶対パスにそのまま書き込むため、After Effects が書ける場所であればモデルはファイルを作成も上書きもできます（唯一の例外はサーバー自身の IPC ディレクトリで、そこへの書き込みは拒否されます）。有効なポリシーは起動時に stderr へ出力され、`ae_catalog` からも返されます。

## ツール

ツールは 11 個です。どのツールを使うかは LLM がプロンプトから自分で選ぶため、直接呼び出す場面はほとんどありません。ツールごとの生成リファレンスは [docs/TOOLS.md](./docs/TOOLS.md) を参照してください。

| ツール                   | 用途                                                                                                                                                                                                                                                                                    |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ae_project_info`        | プロジェクトレベルの情報。ファイルパス、未保存フラグ、全アイテムの種類とサマリ、アクティブアイテム。最初に呼びます。                                                                                                                                                                    |
| `ae_comp_info`           | コンポジションの詳細。サイズ、fps、デュレーション、ワークエリア、モーションブラー、レイヤーサマリ。名前・アイテム id に加え、その配列も渡せます（複数コンポジションを 1 往復で取得）。                                                                                                  |
| `ae_layer_info`          | レイヤーの全情報。Transform / Effects / Masks / Text / Contents のプロパティツリーとキーフレームを含みます。`layerIndex` は配列や `"all"` も受け付け、コンポジション全体の監査が 1 コールで済みます。                                                                                   |
| `ae_render_frame`        | 指定時刻のコンポジションを PNG 1 枚にレンダリングします。エージェントの「目」。変更と組み合わせて視覚フィードバックループを作ります。                                                                                                                                                   |
| `ae_save_project`        | プロジェクトを保存します。`path` を渡すと別名保存です。                                                                                                                                                                                                                                 |
| `ae_project_export_json` | プロジェクト全体を JSON ドキュメントへ直列化します。フォルダ、コンポジション、レイヤー、キーフレーム、エフェクト、マスク、テキスト、シェイプの Contents、マーカー（コンポジションとレイヤー）、タイムリマップ、平面、ファイルフッテージ参照。`outPath` へ書くか、インラインで返します。 |
| `ae_project_import_json` | `ae_project_export_json` が生成したドキュメントからプロジェクトを再構築します。`clearFirst`、`dryRun`（検証のみ）、`skipValidation` に対応します。                                                                                                                                      |
| `ae_version_info`        | AE のバージョン、ビルド、機能プローブ（`saveFrameToPng`、`app.effects`、`Socket`）。                                                                                                                                                                                                    |
| `ae_catalog`             | `ae_do` で使えるアトミックオペレーションの発見。引数なしで全カテゴリ、カテゴリを指定するとオペレーションごとの詳細パラメータ。                                                                                                                                                          |
| `ae_do`                  | アトミックオペレーションを名前で実行します（名前は `ae_catalog` から）。キーフレーム、トランスフォーム、エフェクト、シェイプ、エクスプレッション、コンポジションとレイヤーの編集などをカバーします。                                                                                    |
| `ae_context`             | プロジェクト/コンポジション/選択の周辺状態に加え、`AE.*` ヘルパー一覧、ES3 の規則、undo の契約。セッション開始時に一度呼びます。                                                                                                                                                        |

読み取り中心の作業には専用ツールがあり、変更系の全機能は 2 段階のモデルを通ります。`ae_catalog` がカテゴリ別にアトミックオペレーションをパラメータスキーマ付きで列挙し、`ae_do` が名前で 1 つを実行します。引数は After Effects へ届く前に公開スキーマに対して検証され、すべての応答は周辺コンテキスト（アクティブなコンポジション、選択、プロジェクト状態）を運びます。`eval.run` は、どのアトミックオペレーションも合わないときのオプトイン式の抜け道です。

## 使い方のパターン

### 調査（「このプロジェクトには何がある？」）

1. `ae_project_info()` → アイテム一覧とアクティブアイテム。
2. `ae_comp_info({ nameOrId: ["Main", "Intro"] })` → 複数コンポジションのレイヤー一覧を 1 コールで。
3. `ae_layer_info({ compNameOrId: "Main", layerIndex: "all" })` → 全レイヤーのプロパティ値とキーフレームを 1 コールで（単一インデックスやインデックス配列も渡せます）。

### 視覚的な検証を伴う編集

1. `ae_catalog({ category: "layer" })` → オペレーションとそのパラメータを見つけます。
2. 変更と検証を 1 回の `ae_do` で行います。`batch.run` の子は順番に実行され、`render.frame` や `comp.info` を同じ呼び出しに同乗させられます:

   ```
   ae_do({ operation: "batch.run", args: { ops: [
     { operation: "keyframe.add", args: { comp: "Main", layer: 2, property: ["Transform", "Position"], time: 0, value: [960, 540] } },
     { operation: "render.frame", args: { comp: "Main", time: 0, outPath: "/absolute/path/check.png" } }
   ] } })
   ```

3. クライアントの画像機能で `check.png` を見て、結果を確認します。
4. 違っていたら、もう一度 `ae_do` で修正します。バッチを含め、直前の呼び出しは `project.undo` 一回で丸ごと戻せます。

### JSON によるチェックポイントと復元

- **リスクの高い変更の前にスナップショット:** `ae_project_export_json({ outPath: "/absolute/path/before.json" })`
- **変更を加える**（変更系ツールの任意の組み合わせで）
- **必要なら巻き戻す:** `ae_project_import_json({ inPath: "/absolute/path/before.json", clearFirst: true })`
- **AE に触れずにドキュメントを検証:** `ae_project_import_json({ inPath, dryRun: true })` は計画（アイテム数）だけを返します

### `eval.run` によるカスタム JSX

`AE_MCP_ENABLE_EVAL=1` が必要です。`ae_do({ operation: "eval.run", args: { code: "..." } })` は ES3 の関数本体を実行します。`var` のみ（`let`/`const`、アロー関数、テンプレート文字列は不可）、古典的な `for` ループを使い、最後は `return <JSON にできる値>;` で終えます。コードは呼び出しの自動 undo グループの中で走るので、自分で undo グループを開いてはいけません。`AE.*` ヘルパー（`AE.findCompByNameOrId`、`AE.serializeLayerFull`、`AE.exportProject` など）と、応答へ痕跡を積む `log("message")` が使えます。ヘルパーの全リストと規則は `ae_context` が返します。

## トラブルシューティング

- **すべての呼び出しがタイムアウトする。** After Effects がプロジェクトを開いた状態で起動しているか、環境設定「スクリプトによるファイルへの書き込みとネットワークへのアクセスを許可」が ON かを確認してください。OFF だと AE は応答を書けません。macOS では、MCP クライアントが After Effects の制御を許可されているか（システム設定 → プライバシーとセキュリティ → オートメーション）も確認してください。
- **`AE_NOT_FOUND`。** After Effects が既定のインストール場所にありません。`AE_MCP_EXE` を設定してください。
- **AE が「別のスクリプトの実行中に 2 つ目のスクリプトを実行しようとしました」と警告する。** AE はスクリプトを同時に 1 つしか実行せず、実行中に届いたスクリプトを拒否します。しかもこの警告ダイアログ自体が閉じられるまで全スクリプトをブロックするので、まず OK で閉じてください。サーバー発の呼び出しはビジーロックでプロセスを跨いで直列化され、拒否されたディスパッチは自動でリトライされます。それでも出る場合の典型は、ユーザーがインストールしたパネル/起動スクリプトがその瞬間に動いていたか、同じ AE に対して複数のスクリプト駆動ツール（別の AE 自動化ツール、あるいは同じサーバーの二重登録）が動いているケースです — 片方を外してください。
- **呼び出しが AE をハングさせた:**
  1. `taskkill /F /IM AfterFX.exe`（Windows）/ `pkill -9 -f "Adobe After Effects"`（macOS）
  2. AE を起動し直し、プロジェクトを開いて（または作成して）「準備完了」の状態にします
  3. リトライします
- **さらに調べる:** サーバーは起動時にメールボックスのパスを stderr へ出力します。そのディレクトリの `dispatcher.log` に、各呼び出しが AE 内で何をしたかが記録されています。「no pending request」という行があれば、メールボックスの場所について AE とサーバーの認識がずれています（AE が別ユーザーで動いている場合が典型です）。

## 既知の制限

- **フッテージ欠落時のインポート忠実度。** `ae_project_import_json` はレイヤーを元のスタッキングインデックスで参照します。インポート中にレイヤーがスキップされると（ソースフッテージが見つからず、プレースホルダも解決しない場合）、後続の親インデックス参照が別のレイヤーを指すことがあります。参照フッテージへ到達できる状態を保つか、ソース欠落のあるプロジェクトでは親子付けの手直しを見込んでください。
- **After Effects インスタンスは 1 つ。** 複数の MCP クライアントは安全ですが、全員が同じ AE を操作し、AE は JSX をシングルスレッドで実行します。同時の呼び出しは並列化されず、順番待ちになります。変更をまとめて出すときは `batch.run` で 1 往復に畳んでください。
- **周辺コンテキストはトークン面ではタダではありません。** すべての `ae_do` 応答はアクティブなコンポジションと選択中レイヤーの全リストを運びます。ラウンドトリップは増えませんが、数百レイヤーを選択したコンポジションでは無視できないサイズになります。
- **macOS 対応は日が浅い。** macOS のランチャー（AppleScript / `osascript`）は Windows 側より新しく、実運用の実績がまだ少ない段階です。問題があればイシューで報告してください。
